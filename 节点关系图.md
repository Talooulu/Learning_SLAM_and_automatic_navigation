## 🔄 数据流详细说明

### 1. 传感器数据流

```
Gazebo
  │
  ├─ /points_raw (激光雷达点云)
  │    │
  │    └─→ points_pub_map
  │           │
  │           └─→ /mapokk (map坐标系点云)
  │                  │
  │                  └─→ map_pub
  │                         │
  │                         └─→ /combined_grid (2D地图)
  │
  └─ /odom (里程计数据)
       │
       ├─→ points_pub_map (用于坐标变换)
       ├─→ map_pub (用于确定地图原点)
       ├─→ odom_map_tf (用于发布TF)
       ├─→ astar (用于确定起点)
       └─→ start_nav (用于计算控制指令)
```

### 2. 控制指令流

```
用户点击目标点
  │
  └─→ /goal_pose
       │
       └─→ astar
            │
            ├─→ /path (原始路径)
            │     │
            │     └─→ start_nav
            │
            └─→ /path2 (平滑路径)
                  │
                  └─→ start_nav
                       │
                       └─→ /cmd_vel
                            │
                            └─→ Gazebo (机器人执行)
```

### 3. TF变换链

```
map (地图坐标系)
  │
  └─→ odom (里程计坐标系) [由 odom_map_tf 动态发布]
       │
       └─→ base_footprint (机器人脚部) [静态变换]
            │
            └─→ base_link (机器人本体) [静态变换]
                 │
                 └─→ 各个传感器和关节 [由 robot_state_publisher 发布]
```

## 🎯 关键参数说明

### map_pub 节点参数

- `grid_width = 60.0` - 地图宽度（米）
- `grid_height = 60.0` - 地图高度（米）
- `resolution = 0.1` - 分辨率（米/像素），即每个格子10cm
- `min_height = 0.1` - 点云最小高度（米），过滤地面
- `max_height = 1.0` - 点云最大高度（米），过滤高空障碍物
- `obstacle_radius = 0.2` - 障碍物膨胀半径（米）

### start_nav 节点参数

- `lookahead_distance = 0.5` - 前瞻距离（米），机器人看向前方的距离
- 速度范围：0.6 m/s ~ 1.5 m/s
- 停止距离：0.2 m（距离目标点小于0.2m时停止）

### astar 节点参数

- `expansion_size = 5` - 障碍物膨胀大小（格子数）
- 搜索方向：8方向（上下左右+4个对角线）

## 💡 常见问题

### Q1: 为什么需要 points_pub_map 节点？
**A**: 激光雷达数据是相对于机器人的（base_link坐标系），但建图需要统一的地图坐标系（map坐标系）。这个节点负责将点云从机器人坐标系转换到地图坐标系。

### Q2: 为什么需要多层障碍物膨胀？
**A**: 机器人有体积，不能紧贴障碍物。多层膨胀提供不同级别的安全距离，路径规划时可以选择合适的膨胀层，避免碰撞。

### Q3: 为什么需要路径平滑？
**A**: A*算法生成的路径可能有尖锐转折，机器人无法瞬间改变方向。平滑后的路径更适合机器人跟踪，运动更流畅。

### Q4: 纯追踪算法中的前瞻距离是什么？
**A**: 前瞻距离是机器人"看向前方"的距离。如果前瞻距离太小，机器人会频繁调整方向；如果太大，机器人可能无法及时转弯。0.5m是一个经验值。

### Q5: map、odom、base_link 坐标系的关系？
**A**: 
- `map`: 全局地图坐标系，固定不变
- `odom`: 里程计坐标系，基于轮式编码器，会累积误差
- `base_link`: 机器人本体坐标系，随机器人移动

`map → odom` 的变换由SLAM算法估计，`odom → base_link` 的变换由里程计提供。
